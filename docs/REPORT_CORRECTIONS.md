# Corrections to the original FYP-I report

The original `FYP-Part-1_Report_LLM_Security(1).docx` is preserved. Edit the report manually before submission; this file maps claims in that document to the implemented application as of 24 September 2026. Do not replace reported experimental figures with unmeasured targets.

| Report claim/location | Accurate implementation statement |
|---|---|
| Abstract and Chapters 3–4 describe five development phases, including Docker/Linux deployment and a later Red Team frontend. | The current implementation plan is three local application phases; deployment is explicitly excluded. The Red Team UI exists locally, but its live RabbitMQ/provider flow is not signed off in this workspace. Distinguish historical proposal from implemented work. |
| Chapter 4.1.1 says passwords use bcrypt work factor 12 and JWTs expire after 24 hours. | Current `core/security.py` uses `pbkdf2_sha256`; JWT default expiry is 60 minutes (configurable), HS256, with `sub` user ID, `ver` token version, `iat`, and `exp`. Current-user lookup rechecks active/verified account and company. |
| Chapter 4.1.1 says tenant identity comes from an `organization_id` JWT claim. | Tenant is derived from the current verified user database record; resource queries carry `company_id`. Never trust a client-selected tenant. |
| Chapters 3–4 describe Guardrails AI middleware and a 60-second policy cache intercepting all prompts. | Ordinary `/api/prompt-workspace/run` calls use `ProtectedPromptService` with Mongo policy/version snapshots and registered deterministic/semantic validators. It protects traffic through this API only; it does not intercept direct traffic to outside providers. No middleware/cache claim should be made unless measured and implemented. |
| Chapter 4.1.4 says jobs contain generated prompts/integration IDs on RabbitMQ, each attack runs in a subprocess, and one result document is created per attack. | Mongo `red_team_tests` and `red_team_jobs` hold immutable synthetic manifest, durable dispatch intent, and final result. Rabbit messages contain only version, job ID, test ID, and generation. A Python worker thread handles the call while the Pika channel thread stays responsive; prompt text is never executed as a shell command. Provider adapters are reused. |
| Chapter 4.1.4 says `prefetch_count=1` prevents rate-limit violations and queue retries automatically on rejection. | Prefetch limits deliveries per consumer, not provider quota. A shared Mongo integration lease/pacing service initially permits one in-flight call and six/minute. Only confirmed rate-limit responses receive bounded persisted retry; ambiguous post-dispatch errors are not replayed. |
| Chapter 4.1.4 says all Red Team tests bypass guardrails. | Raw mode intentionally bypasses platform policy; protected mode invokes the same protected execution path as Prompt Studio using frozen policy context. Both use the same synthetic scenarios. |
| Chapter 3 diagrams use separate `RED_TEAM_CONFIG` and `RED_TEAM_RESULT` documents. | Use `red_team_tests` and `red_team_jobs`; one job row is both dispatch intent and authoritative outcome. Update ER diagram, collection names, and API examples accordingly. |
| Chapter 5 reports 90% overall accuracy and related category rates. | Treat these as historical/proposed figures unless the original dataset/method can be reproduced. The actual small local Phase 2 evaluation is documented in `docs/EVALUATION_RESULTS.md`, with misses and p95 limits; it is not a production safety claim. The bounded exact-evidence Red Team catalog has no measured live-model accuracy yet. |
| Chapter 4 examples contain a person's name and SSN request. | Use fabricated synthetic identifiers/markers in demonstrable tests and screenshots. No real PII, real secrets, or external exfiltration targets are required by the current catalog. |

Also reconcile report title/branding to **Sentinel AI**, figure labels/logo, phase numbering, status tense, and any document date versus experiment date. Review the abstract's 2025–2026 incident claims and references against their original sources before submission; this implementation work did not verify those external historical claims. Mark proposed Docker deployment and production benchmarks as future work, not achievements. `docs/TEST_RESULTS.md` is the current evidence boundary.
