# Product

## Register

product

## Users

Organization administrators configure users, groups, provider integrations, and security policies. Employees use Prompt Studio within their assigned organization. A local platform administrator manages organization status. These users need to understand what is configured, what is actually enforced, and which actions require attention.

## Product Purpose

Build a trustworthy workspace for administering an LLM-security application. In Phase 1, an administrator can establish an organization, invite and manage people, configure integrations and scoped policies, and review administration activity. Policies are configuration only until Phase 2; the interface must never imply that a configured policy currently protects a prompt.

## Brand Personality

Calm, precise, trustworthy. The product should feel familiar to users of well-made administrative tools: direct language, clear state, and efficient workflows without decorative effects competing with the task.

## Anti-references

Avoid fake live analytics, inflated security claims, decorative dashboard cards, excessive motion, ambiguous status colors, and unusual controls for standard form or table actions. Do not trade clarity for a cyber-security aesthetic.

## Design Principles

1. Show real system state and name unavailable capabilities honestly.
2. Make each administration task easy to locate, complete, and recover after an error.
3. Keep permissions, scope, and dependency conflicts understandable before an action is committed.
4. Favor predictable, consistent interaction patterns across all administration pages.
5. Preserve useful density while keeping critical status and warnings immediately legible.

## Accessibility & Inclusion

Aim for WCAG 2.2 AA where practical. All core workflows should be keyboard-accessible, have visible focus and text labels, communicate validation without relying on color alone, respect reduced motion, and remain usable on narrow screens.
