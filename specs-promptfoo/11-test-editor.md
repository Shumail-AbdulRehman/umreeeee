## Goal

Let an admin configure a promptfoo red-team test in one screen — purpose, target, mode, plugins, strategies, grader — see the estimated test case and target call counts, then save it as a draft or launch it.

## Scope

- Rebuild from `design/red-team/v3/new-test.html` in the app's components, not prototype code. Form plus sticky summary; stack at narrower widths. Draft inputs: name, purpose (20–2000 trimmed characters, matching spec 16), target integration/model metadata, raw/protected mode, subject for protected, grader integration/model and cases per plugin (1–10).
- Use capabilities for plugin metadata (with hosted/multi-turn badges), category/strategy labels, severity chips and framework quick-selects for the frameworks in capabilities (nine). A quick-select merges only offered IDs, deduplicates, preserves existing selections, and explains unmapped controls. Hosted strategies show a "Hosted generation" badge and multi-turn strategies show their extra target calls per test case.
- Estimate test cases and target calls separately using the server-supplied multipliers; basic is implicit once. Above 200 estimated target calls show the limit and disable Save and Launch. Missing grader, mismatched model or missing protected subject produces a field error. Clear a selected model when its integration changes and clear protected subject when leaving protected mode.
- **promptfoo config preview** (supervisor's flow: the UI generates the promptfoo config). `ConfigPreview.jsx` shows the YAML string it receives as a prop (from spec 16's redacted preview) in a labelled, focusable, vertically scrollable monospace region below the summary, titled "promptfoo config". It shows loading, error ("Could not build the config preview.") and stale states ("Changed since the last preview"); a "Refresh preview" button raises `onPreview(values)`; never edits or re-derives the YAML client-side. The editor raises `onPreview` once when opened with valid values and on demand.
- Use existing tokens only; no raw colour values. Group labelled controls with fieldsets; keyboard can select options and reach the summary in reading order; invalid submit focuses the first invalid field; keep reduced motion free of transforms. Actions: "Save draft" and "Launch test" (raises `onLaunch(values)`); when capabilities report promptfoo unavailable or the Cloud API key missing, Launch is disabled with that specific reason and Save still works. Copy is plain and specific; the summary states that test cases are generated by promptfoo's hosted service and graded by the selected grader model.
