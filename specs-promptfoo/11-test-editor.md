## Goal

Let an admin configure a promptfoo red-team test in one screen — purpose, target, mode, plugins, strategies, grader — see what it will cost in attacks and target calls, then save it as a draft or launch it.

## Scope

- Rebuild from `design/red-team/v3/new-test.html` in the app's components, not prototype code. Form plus sticky summary; stack at narrower widths. Draft inputs: name, purpose (2–2000 trimmed characters), target integration/model metadata, raw/protected mode, subject for protected, grader integration/model and cases per plugin (1–10).
- Use capabilities for plugin metadata (with hosted/multi-turn badges), category/strategy labels, severity chips and four framework quick-selects. A quick-select merges only offered IDs, deduplicates, preserves existing selections, and explains unmapped controls. Hosted strategies show a "Hosted generation" badge and multi-turn strategies show their extra target calls per attack.
- Estimate attacks and target calls separately using the server-supplied multipliers; basic is implicit once. Above 200 estimated target calls show the limit and disable Save and Launch. Missing grader, mismatched model or missing protected subject produces a field error. Clear a selected model when its integration changes and clear protected subject when leaving protected mode.
- Use existing tokens only; no raw colour values. Group labelled controls with fieldsets; keyboard can select options and reach the summary in reading order; invalid submit focuses the first invalid field; keep reduced motion free of transforms. Actions: "Save draft" and "Launch test" (raises `onLaunch(values)`); when capabilities report promptfoo unavailable or the account email missing, Launch is disabled with that specific reason and Save still works. Copy is plain and specific; the summary states that attacks are generated by promptfoo's hosted service and graded by the selected grader model.
